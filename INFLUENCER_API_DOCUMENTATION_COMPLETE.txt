1.3 REFRESH TOKEN
-----------------
Endpoint: POST /auth/refresh
Description: Get new access token using refresh token

Request Body:
{
  "refreshToken": "your_refresh_token_here"
}

Response (200):
{
  "accessToken": "new_access_token",
  "refreshToken": "new_refresh_token"
}

1.4 LOGOUT
----------
Endpoint: POST /auth/logout
Description: Logout user and invalidate tokens

Request Body:
{
  "refreshToken": "your_refresh_token_here"
}

Response (200):
{
  "message": "Logged out successfully"
}

3.2 INSTAGRAM OAUTH FLOW
------------------------
Step 1: GET /social/instagram/auth
Response: Redirects to Instagram OAuth authorization page

Step 2: User authorizes on Instagram
Step 3: Instagram redirects to /social/instagram/callback
Step 4: Success redirect to frontend with tokens

3.3 TIKTOK OAUTH FLOW
---------------------
Step 1: GET /social/tiktok/auth
Response: Redirects to TikTok OAuth authorization page

Step 2: User authorizes on TikTok
Step 3: Success redirect to frontend

3.4 DISCONNECT SOCIAL ACCOUNT
-----------------------------
DELETE /social/instagram/disconnect
DELETE /social/tiktok/disconnect

Response (200):
{
  "message": "Instagram disconnected successfully"
}

3.5 REFRESH SOCIAL TOKEN
------------------------
POST /social/instagram/refresh
POST /social/tiktok/refresh

Response (200):
{
  "message": "Token refreshed successfully"
}

11. DATA FORMATS & VALIDATION RULES
================================================================================

CONTENT CATEGORIES:
["Fashion", "Beauty", "Lifestyle", "Travel", "Food", "Fitness", "Technology", "Gaming", "Art", "Music", "Sports", "Business", "Education", "Health", "Photography", "Dance", "Comedy", "Motivation", "Reviews", "DIY"]

EMAIL FREQUENCY:
"immediate" | "daily" | "weekly"

PLATFORM TYPES:
"instagram" | "tiktok"

APPLICATION STATUSES:
"applied" | "approved" | "rejected" | "submitted" | "approved" | "disputed"

USER STATUSES:
"active" | "adminpending" | "suspended" | "inactive"

VALIDATION RULES:
- Email: Valid email format, unique across all models
- Password: Minimum 6 characters
- Username: 3-30 chars, alphanumeric + underscore only, unique
- Bio: Maximum 500 characters
- URLs: Valid HTTP/HTTPS URLs
- Phone: Valid phone number format
- contentUrl: Valid URL format
- quietHours.from/to: HH:MM format (e.g., "22:00")

FIELD MAPPINGS:
- API "basicInfo.fullName" → Model "name" (top-level field)
- API "basicInfo.username" → Model "username" (top-level field)
- API "basicInfo.bio" → Model "bio" (top-level field)
- API "contactInfo.location" → Model "contactInfo.location" (String field)
- API "location" → Model "location" (Object with city, country, state, coordinates)
